# ACP-002: Record architecture boundaries

## Problem
The control plane will fail if ownership between goal, planner, policy, skills, agents, and UI is not explicit.

## Scope
- Document which service owns each responsibility.
- Document allowed dependencies between layers.
- Document what must remain behind stable adapters.

## Out of Scope
- Code changes.
- New runtime features.

## Acceptance Criteria
- A single architecture note describes each boundary.
- The note clearly separates orchestration, policy, evidence, and UI.
- The note identifies where adapter boundaries are required.

## Dependencies
- ACP-001

## Validation
- Architecture review against the staged implementation plan.
